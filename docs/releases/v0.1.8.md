# v0.1.8 — Compatibilité ESPHome et contrôles OTA techniques

Release expérimentale de **sources** pour TPP06 / Linux Anyka ARMv5.
Elle corrige la compilation avec ESPHome 2026.11.0 et conserve la compatibilité
logicielle testée avec 2026.10.2. Aucun firmware personnel n'est distribué.

## Corrections et protections

- Adaptation des interfaces GPIO au changement de contrat d'ESPHome 2026.11,
  avec prise en charge de l'ancien contrat et tests des deux ordres d'inclusion.
- Identification du fil principal pour le nouvel ordonnanceur ESPHome.
  Les pilotes Linux des relais et la politique de démarrage sont inchangés.
- Contrôle de l'exécutable après compilation et avant l'envoi OTA normal :
  ELF32 ARM little-endian, EABI5 soft-float, absence de chargeur dynamique,
  segments non tronqués et point d'entrée dans un segment exécutable.
  Le programme n'est jamais exécuté sur la machine de compilation pour ce test.
- Contrôle du fichier effectivement sélectionné, y compris `--file` avec un
  YAML. Le cache rapide de validation de cette cible est désactivé pour
  réinstaller le contrôle lors d'un envoi. Le transport et le chiffrement
  restent ceux d'ESPHome.
- **Aucune liste de versions autorisées.** Une nouvelle version ESPHome n'est
  pas bloquée pour son numéro. La validation, la compilation et les contrôles
  techniques doivent réussir ; une API de contrôle absente est signalée.
- Guides français/anglais mis à jour ; modèles complets et pilotes épinglés
  au même tag. Photos du boîtier et compteur de téléchargements conservés.

## Validation et limites

**231 tests automatisés réussis sur chacun des environnements ESPHome
2026.10.2 et 2026.11.0, aucun ignoré.** Ils couvrent notamment la génération C++,
les contrats GPIO/threads, l'acceptation de nouveaux numéros de version simulés
et le refus d'un mauvais fichier avant tout transport réseau.

La correction a été compilée dans ESPHome Device Builder sur Home Assistant
avec 2026.11.0. Le binaire ARMv5 statique obtenu a été inspecté, et les nouveaux
contrôles ont réussi pendant cette compilation. Ce binaire privé n'est pas
fourni dans la release. Les modèles publics ont passé la validation et la
génération C++ ; ils ne sont pas le programme privé utilisé pour cet essai.

**Aucune OTA ni aucun redémarrage n'a été effectué pour ces corrections.**
Leur acceptation sur le panneau après installation reste à faire. Les tests
avec un numéro de version simulé ne valident pas le code d'une future version
d'ESPHome.

Les contrôles ne prouvent pas la compatibilité de chaque instruction ARMv5,
des appels système Linux, ni la stabilité de tous les pilotes à l'exécution.
Ils ne constituent ni une signature de firmware ni un verrou du récepteur OTA.
Un outil extérieur, un envoi sans YAML ou des pilotes modifiés peuvent les
contourner. Garder la toolchain ARMv5, les sauvegardes, la vérification de place
disponible et un essai après installation. Le secours Tuya n'est pas un retour
automatique au précédent ESPHome.

## Télécharger et mettre à jour

- **TPP06-HA-Panel-v0.1.8-sources.zip** : sources publiques, modèles YAML,
  pilotes, outils, tests et documentation, sans historique Git.
- **TPP06-HA-Panel-v0.1.8-SHA256SUMS.txt** : empreinte SHA256 du paquet.

Le compteur GitHub concerne les téléchargements des assets, pas les appareils
installés. Les archives automatiques « Source code » sont distinctes du paquet
nommé ci-dessus.

Suivre le [guide français](https://github.com/Philiphall6/TPP06-smart-panel-project/blob/v0.1.8/docs/fr/DEMARRER-ICI.md).
Le point d'entrée complet est `esphome/tpp06-lvgl-complete.yaml`.
Pour un panneau existant, conserver son YAML privé, ses clés, son nom, ses
entités et ses réglages de relais/BLE. Mettre à jour les sources de composants
vers ce tag ; une copie locale des anciens pilotes ne se met pas à jour seule.
Les paramètres publics laissent les relais en observation et le BLE désactivé.

Compiler dans HA, vérifier la place disponible, puis effectuer un seul envoi
OTA lorsque l'installation est prête à être surveillée. Ne pas réinstaller le
superviseur, modifier le Wi-Fi ni réécrire le logo NAND pour cette mise à jour.

Le paquet ne contient aucun YAML personnel, secret d'installation, journal,
dump, sauvegarde ou binaire privé. Les valeurs déterministes des tests sont
des fixtures publiques, à ne jamais utiliser sur un appareil. Cette publication
ne modifie ni l'historique Git ni les assets d'anciennes releases.

## English

Experimental **source-only** release. Fixes the host GPIO contract and main-loop
thread identification for ESPHome 2026.11.0, with software tests on 2026.10.2 too.
Adds executable checks after compilation and before normal configured OTA:
ELF32 little-endian ARM EABI5 soft-float, no dynamic loader, valid segments and
an executable entry point. Existing transport/encryption are unchanged.

**No version allowlist:** new ESPHome numbers are accepted. Actual configuration,
build and executable checks must pass. Simulated version-number tests do not
establish compatibility with future ESPHome code.

**231 automated tests passed on each tested ESPHome release, none skipped.**
The correction was built in HA with 2026.11.0 and the private static ARMv5 image
was inspected. Public templates passed validation/C++ generation; no personal
firmware is published. **No OTA/reboot was performed for these corrections;
hardware acceptance remains pending.** Checks cannot prove instruction/syscall
compatibility or runtime stability and can be bypassed by external upload tools.

Download the versioned source ZIP and SHA256. Preserve private settings, keys
and commissioned relay configuration; build in HA and check OTA free space.
No Linux supervisor reinstall, Wi-Fi change or NAND write is required.
[English guide](https://github.com/Philiphall6/TPP06-smart-panel-project/blob/v0.1.8/docs/en/START-HERE.md).
